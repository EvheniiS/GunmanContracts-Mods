# Adding your own weapon with Weapon Framework

This guide takes you from nothing to your own weapon on the arsenal panel in The Range: the player pages to it
with `+` / `-`, presses **Retrieve**, the wall slot slides out with your item on it, and they take it off the wall.

A complete, compiling example is in [`Example/`](Example/): `ExampleBaton.cs` (about 120 lines) puts a copy of the
crowbar on the panel. Read it alongside this guide.

## 1. What the framework does and doesn't do

**It does:**
- Adds a real entry to the game's Big Guns arsenal panel: your name, your picture, "ARSENAL 007 / 007".
- Makes the entry owned and free, and hides the ammo, modify and buy buttons for it.
- Builds a wall slot for it the way the game builds the bow's, and gives you a **mount** (a Transform at the slot's
  gun position) when the player retrieves it.
- Tells you when the slot has finished sliding in, and when another weapon replaced it.
- Keeps the save file clean: the game never saves your entry's position or id, so removing your mod (or the
  framework) can't break a save.

**It doesn't:** spawn, hold, holster, save or restore your items. What hangs on the mount, and what happens after the
player takes it, is your mod's code.

## 2. Project setup

Copy [`Example/ExampleBaton.csproj`](Example/ExampleBaton.csproj) and rename it. What matters in it:

```xml
<TargetFramework>net6.0</TargetFramework>
<!-- MelonLoader and the game's interop assemblies (generated by MelonLoader on the first game start) -->
<Reference Include="MelonLoader">                 ...\MelonLoader\net6\MelonLoader.dll
<Reference Include="0Harmony">                    ...\MelonLoader\net6\0Harmony.dll
<Reference Include="Il2CppInterop.Runtime">       ...\MelonLoader\net6\Il2CppInterop.Runtime.dll
<Reference Include="Il2Cppmscorlib">              ...\MelonLoader\Il2CppAssemblies\Il2Cppmscorlib.dll
<Reference Include="UnityEngine.CoreModule">      ...\MelonLoader\Il2CppAssemblies\UnityEngine.CoreModule.dll
<Reference Include="UnityEngine.PhysicsModule">   ...
<Reference Include="Il2CppHurricaneVR.Framework"> ...   the game's classes (ANB*, HVR*)
<Reference Include="Il2CppGD_Game">               ...   GD_HVROptimiser (see step 6)
<!-- WeaponFramework.dll: compile against it, never ship it -->
<Reference Include="WeaponFramework"><HintPath>...\Mods\WeaponFramework.dll</HintPath><Private>false</Private></Reference>
```

Every reference has `<Private>false</Private>`: the game already has these DLLs, and players install
`WeaponFramework.dll` from its own download. (Inside this repo the example uses a `ProjectReference` instead.)

Put your game folder in `GameDir.local.props` next to the project, or pass `-p:GameDir="D:\...\Gunman Contracts - Stand Alone"`.

## 3. Required or optional?

Decide whether your mod works without the framework.

- **Required** (your weapon only exists on the panel):
  ```csharp
  [assembly: MelonAdditionalDependencies("WeaponFramework")]
  ```
  MelonLoader then refuses to load your mod without it and says why.
- **Optional** (your mod has another way to get the weapon, like Billy Clubs' spawn key):
  ```csharp
  [assembly: MelonOptionalDependencies("WeaponFramework")]
  ```
  and call the framework only from **one method marked `[MethodImpl(MethodImplOptions.NoInlining)]`**, after checking
  the assembly is loaded. .NET resolves a DLL the first time a method that uses it is compiled, so keeping every
  framework type inside that one method means a missing DLL never crashes you:
  ```csharp
  bool loaded = false;
  foreach (var a in AppDomain.CurrentDomain.GetAssemblies())
      if (a.GetName().Name == "WeaponFramework") { loaded = true; break; }
  if (loaded) RegisterArsenal();
  ```

## 4. Register once

From `OnInitializeMelon`:

```csharp
WeaponFramework.Arsenal.Register(new WeaponFramework.ArsenalWeapon
{
    Id = "ExampleBaton",          // unique, letters and digits only
    DisplayName = "Example Baton",// the panel prints it upper case
    Description = "",             // keep empty: the panel draws it over the name
    Icon = myTexture,             // see step 7; null = no picture
    OnShown = Hang,               // Retrieve pressed: put your items on the mount
    OnSettled = Align,            // optional: the slot finished sliding in
    OnHidden = WentBack,          // optional: another weapon was retrieved
});
```

The entry appears the next time The Range builds its arsenal, so registering in `OnInitializeMelon` is always early
enough. The log confirms it: `[Weapon Framework] arsenal (load): 1 mod entry added after the game's 6 (ExampleBaton)`.

## 5. The three callbacks

| Callback | When | What to do there |
|---|---|---|
| `OnShown(Transform mount)` | Right after the player presses Retrieve. The slot is **still inside the wall** and about to slide out. | Spawn or move your items onto `mount`: parent them to it (they then ride the animation), make them kinematic. **It runs on every retrieve**, so only fill what is missing (the player may already carry the item). |
| `OnSettled(Transform mount)` | The wall's switch animation has ended (the game's `ANBGunwall.endAnimation`). Positions are final. | Anything that measures the world: raycasts to the board, final offsets. **Never measure in `OnShown`**: the slot is still moving and your ray will hit the wall around it. |
| `OnHidden()` | Another weapon was retrieved. Your slot slides back into the wall and is switched off, children included. | Usually nothing. Items still on the mount go in with it and are there again on the next retrieve. |

**The mount's axes** (measured): `mount.up` runs **along** the wall, `mount.forward` points **up**, and `mount.right`
is the wall normal, pointing **into** the wall. So "towards the player" is `-mount.right`. The board surface is about
**6 cm behind** the mount (Billy Clubs' ray measured `plate_2` at 6 cm). The board is roughly 0.7 m wide and 0.5 m
tall, and its middle is a few cm above the mount.

## 6. Making your item grabbable: two game traps

**Trap 1: the game's grabbable optimiser switches your item off.** `GD_HVROptimiser` collects every grabbable in the
scene **once**, including inactive ones (so your hidden template too), switches them all off, and afterwards switches
back on only those that are close and in front of the player. A copy of your disabled template starts ungrabbable,
and since it isn't in the optimiser's list, nothing ever turns it on. After every `Instantiate`:

```csharp
var list = GD_HVROptimiser.instance != null ? GD_HVROptimiser.instance._grabbables : null;
foreach (var g in go.GetComponentsInChildren<HVRGrabbable>(true))
{
    g.enabled = true;
    list?.Remove(g);
}
```

Items that existed before the optimiser's first scan are in its list and switch off whenever they're behind the
player (a holstered item that "sometimes won't draw"). If your items live long, repeat the removal once a second, as
`Daredevil/BillyClubs/Optimiser.cs` does.

**Trap 2: `Instantiate` wakes everything in the copy.** Game components often register themselves in a global slot in
`Awake`. A copy that wakes up takes over that slot, and when it's destroyed the game crashes later somewhere
unrelated. Make your template by copying under an **inactive** parent (nothing wakes), as the example does, and strip
components you don't need before the template is ever activated.

**Taking it off the wall:** every grab (hand, force grab, socket) goes through `HVRGrabberBase.GrabGrabbable`. A Harmony
prefix there is the place to unparent your item from the mount and make it non-kinematic (see `GrabPatch` in the
example).

**Don't put your item in the slot's socket.** The slot's own gun socket (`gunstorage`, a `DemoHolster`) only accepts
guns and knives and throws on anything else. The framework switches it off; parent to the mount instead.

## 7. The panel picture

The game's pictures are white/light-grey shaded renders of the model with a dark outline, on a transparent
background, about 2.15:1 (the bow's is 1364 × 635). Anything that size works; a dark or coloured picture looks
out of place on the blue panel.

Billy Clubs renders its own from the model in Blender, headless: [`BlenderRefs/render_arsenal_icon.py`](../BlenderRefs/render_arsenal_icon.py)
(Workbench, white clay + outline pass, and a texture pass for light/dark parts) and
[`make_arsenal_icon.py`](../BlenderRefs/make_arsenal_icon.py) (combines them). Change the OBJ path and the layout.

Ship the PNG inside your DLL as an embedded resource and load it:

```csharp
using var s = Assembly.GetExecutingAssembly().GetManifestResourceStream("MyMod.icon.png");
using var m = new MemoryStream(); s.CopyTo(m);
var tex = new Texture2D(2, 2, TextureFormat.RGBA32, false);
ImageConversion.LoadImage(tex, m.ToArray(), false);      // needs UnityEngine.ImageConversionModule
tex.hideFlags = HideFlags.DontUnloadUnusedAsset;
```

## 8. Test checklist

1. `[Weapon Framework] registered 'YourId'` at start, and `arsenal (load): … added` in The Range.
2. The panel shows `ARSENAL 007 / 007` (or more), your name and picture, a Retrieve button, no ammo counter.
3. Retrieve: your item slides out with the slot and sits where you want it after the slide.
4. Grab it with each hand, and with the force grab (point and pull).
5. Retrieve another weapon, then yours again: nothing is duplicated, nothing is lost.
6. Restart the game with your entry selected last: the wall starts on one of the game's weapons (the framework logs
   `save: wall index 6 is a mod entry - saved as N` with `DebugLog = true`).
7. Remove your mod (and the framework): the game and the save still work.

`[WeaponFramework] DebugLog = true` in `UserData\MelonPreferences.cfg` logs every step: the slot, the mount position,
retrieve, settle and save.

## 9. Limits

- **Big Guns wall only.** The pistol wall builds its slots differently.
- **The Range only.** It is the only scene with the arsenal. Carrying your item into contracts is up to your mod
  (Billy Clubs does it with its own belt holsters and a saved state).
- **One mount per entry.** Hang several items on it yourself (Billy Clubs hangs two).

## API reference

```csharp
namespace WeaponFramework
{
    public sealed class ArsenalWeapon
    {
        public string Id;                     // required, unique
        public string DisplayName;            // defaults to Id
        public string Description = "";
        public Texture2D Icon;                // may be null
        public Action<Transform> OnShown;     // Retrieve pressed (slot still moving)
        public Action<Transform> OnSettled;   // slot in place
        public Action OnHidden;               // replaced by another weapon
    }

    public static class Arsenal
    {
        public static void Register(ArsenalWeapon w);   // once; a second Id is ignored with a warning
    }
}
```

Exceptions thrown in your callbacks are caught and logged by the framework; they don't break the panel.
